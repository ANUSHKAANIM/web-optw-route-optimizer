# Neural policy + beam search (decomposition approach)

## What this is

`beam-search.ts` wraps the single-agent PointerNetwork checkpoint
(`model/optw_model.onnx`, exported from the repo root's `optw_model.pth`,
retrained 2026-09-29) with beam search, scored against THIS project's own
feasibility engine (`computeNodeStates`), not the model's own built-in
notion of admissibility.

Multi-team coordination is handled by **decomposition, not joint training**:
each team's beam search receives `alreadyVisited` (every origin already
evacuated by any OTHER team, computed in `game.service.ts`) and the shared
`demandServedSoFar`/`shelterCapacity` pool, so no two teams can be assigned
the same village or jointly exceed the shelter's capacity. There is no
learned coordination beyond that shared exclusion -- the model itself was
never trained with multiple simultaneous agents in its state.

## Documented mismatches between the trained model and the evacuation objective

1. **No demand/capacity in the model's state or reward.** `env.py`'s
   reward is a random 1-9 integer per node; the model has never seen
   population demand or a shelter capacity constraint. We substitute
   risk-weighted priority as "reward" when building features, but the
   model wasn't trained to reason about a shared, depletable capacity pool
   at all -- that's enforced entirely externally, by masking.
2. **No multi-agent state.** `env.py`'s `batch_size` is parallel
   *independent* training episodes, not cooperating agents sharing one
   instance. The model has no notion of "another team already went here."
3. **Trivial accessibility windows during training.** `train.py` always
   calls `OPTWEnvironment(..., enable_forecast_events=False)`, under which
   `opening_times = 0` and `closing_times = max_time` for every node, every
   episode. The model has never actually had to learn to route around a
   node-specific deadline -- our evacuation nodes' real restricted-access
   windows are out-of-distribution input for it.
4. **Travel time isn't literally coordinate distance.** Training coords
   are i.i.d. uniform in [-1, 1] with Euclidean "distance = travel time".
   Our graph's coordinates are also an abstract (x, y) plane (not
   real-world geography, so no mismatch there), but travel time comes from
   the graph's own point-to-point minutes (`AVG_TRAVEL_SPEED_KMH`-derived),
   not literally the Euclidean distance between the fed coordinate
   features -- the two are close but not generated by the identical
   process the model learned from.

None of this means the model is useless here -- it means any reward
advantage beam search shows over the greedy baseline must be read as
"this decomposition, on this data, right now," not as a validated claim
that reinforcement learning solves the evacuation problem. See
`beam-search.test.ts` and `model/evaluate_evacuation.py` (if present) for
the actual measured comparison.

## Why beam search, not just greedy

Beam search (`beamWidth` partial routes kept at each step, scored by
cumulative log-probability, final pick by realized total reward among all
completed candidates) strictly dominates greedy decoding in principle --
greedy is the beamWidth=1 special case -- at the cost of `beamWidth`×
inference calls per step. `beamWidth` and `maxDepth` are both plain
function parameters, not hardcoded constants.
